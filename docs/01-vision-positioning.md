# 01. Vision & Positioning

## 포지셔닝 선언문

> "아이디어 구상부터 수익화(결제, 광고, 검증)까지 — 바이브코딩의 전 과정에서 발생하는 마찰을 단계별로 낮춰주는 AI 네이티브 올인원 플랫폼"

경쟁 구도를 좌표로 잡으면:

- **Product Hunt류(공개 검증)** + **Gumroad류(결제/수익공유)** + **BetaList류(스모크테스트)** + **Bubble/Replit류(노코드-바이브코딩 실행)** 를 하나의 퍼널로 연결
- 차별점은 개별 툴이 아니라 **"프롬프트 한 줄에서 시작해 실제 매출 1원까지" 이어지는 단일 여정(single funnel)**

## 타겟 사용자 (Phase별로 넓어짐)

| Phase | 주 타겟 | 니즈 |
|---|---|---|
| 1 | 프롬프트 엔지니어링에 관심있는 크리에이터/마케터 | 좋은 프롬프트 발견·공유·버전업 |
| 2 | 이미지/영상 생성 실무자 | 모델별 결과물 비교, API 비용 절감 |
| 3 | 1인 창작자, 커머스 셀러 | 3D 에셋/숏폼/상세페이지 자동 제작 |
| 4 | 바이브코더, 사이드프로젝트 개발자 | 사업자등록·PG·광고 없이 결제 붙이고 검증받기 |
| 5 | 문제는 있지만 개발력 없는 사람 | AI로 요구사항 구조화 후 개발자에게 발주 |

## Phase별 노스스타 지표 (초안)

| Phase | 핵심 지표 | 의미 |
|---|---|---|
| 1 | 프롬프트 등록 수, 버전업(포크) 비율 | 위키형 협업이 실제로 돌아가는지 |
| 2 | 유료 크레딧 전환율, 모델별 비교 세션 수 | 과금모델이 실제로 먹히는지 |
| 3 | 파이프라인 산출물 수, 결과물→공유 전환율 | 자동화 도구의 실사용 가치 |
| 4 | 결제모듈 연동 완료 프로젝트 수, 스모크테스트 신청 수 | 진짜 차별화 지점의 검증 |
| 5 | 매칭 성사율, 매칭 후 수익공유 발생 건수 | 마켓플레이스 유동성 |

## 왜 이 순서가 아니어도 되는가

Phase 2와 3은 시장 신호에 따라 순서가 바뀔 수 있음을 전제로 설계한다 (`CLAUDE.md` 원칙 D 참조). 예: 게임 파이프라인(Phase 3 일부)이 예상보다 먼저 인기를 끌면, 모델 레지스트리 구조 덕분에 별도 재설계 없이 메인 화면에 노출 가능해야 한다.

## 비즈니스 모델 요약

| 레이어 | 수익원 |
|---|---|
| Phase 2 | 생성 API 원가 대비 약 40% 마진 (크레딧 판매) |
| Phase 3 | 파이프라인 사용료 또는 구독 |
| Phase 4 | 결제모듈 수수료, 애드센스 수익 분배, 스모크테스트 유료 리포트 |
| Phase 5 | 매칭 수수료, 매칭 후 지속 수익공유 |

## 알려진 리스크 (초기부터 인지)

1. API 재판매 마진 구조는 모델사 정책 변경에 취약 — 복수 벤더 계약으로 리스크 분산
2. 애드센스 대량/저품질 콘텐츠 정책 위반 리스크 — Phase 3부터 품질 게이트 필요
3. 결제/광고 대행은 전자상거래법, 표시광고법 소지 가능 — Phase 4 착수 전 법률 검토 필수
4. Phase 전체를 동시에 벌이면 리소스 분산 — MVP는 Phase 1+2로 좁혀서 검증
