# 09. Design System — PLAYLAB UI 정의

> 이 문서는 첨부된 목업(PLAYLAB)을 기준으로 화면/컴포넌트를 정의한다.
> 각 화면은 `docs/02-architecture-core-principles.md`의 모듈 레지스트리, `docs/06-ui-layout-system.md`의 슬롯 구조와 1:1로 매핑되도록 설명을 붙였다. 즉 이 목업은 "완성된 화면"이 아니라 **Phase 1~4 모듈이 각자의 슬롯/모듈 화면으로 이미 다 켜진 상태의 참고 이미지**로 취급한다. 실제 개발 시 Phase 1만 켜져 있어도 레이아웃 골격은 이 문서 기준으로 잡는다.

---

## 0. 브랜드 아이덴티티

| 항목 | 값 |
|---|---|
| 서비스명 | PLAYLAB |
| 로고 | 좌상단, 보라색 배지 아이콘 + 워드마크, 사이드바 최상단 고정 |
| 브랜드 컬러 | Violet/Purple 계열 단일 액센트 (`accent`) — 버튼, 활성 탭, 배지, 진행바 등 인터랙션 요소에 일관되게 사용 |
| 기본 모드 | 다크 모드 우선 설계 (스크린샷 기준 다크가 default로 보임), 라이트 모드는 동일 토큰 반전 |
| 톤앤매너 | 크리에이티브 툴 특유의 카드 기반 그리드, 게이밍/제작 도구 느낌의 아이콘 일러스트 사용 |

## 1. 전역 레이아웃

```
┌──────────┬──────────────────────────────────────────────┐
│          │  Header: 검색 / 알림 / 다크모드 토글 / 계정 / [+ 새로 만들기] │
│ Sidebar  ├──────────────────────────────────────────────┤
│ (고정)    │                                                │
│          │              Main Content (라우트별 교체)         │
│          │                                                │
└──────────┴──────────────────────────────────────────────┘
```

- **좌측 사이드바**: 폭 고정, 항상 노출(데스크톱). 모바일에서는 `docs/06`에서 정의한 하단 탭바로 전환.
- **헤더**: 통합 검색창("아이디어, 프롬프트, 프로젝트를 검색하세요"), 알림, 다크모드 토글, 계정 메뉴, 우측 끝 `+ 새로 만들기` CTA(항상 고정 노출 — 모든 Phase에서 "생성" 진입점 역할).
- **메인 영역**: 현재 라우트에 따라 전시실 / 프로젝트 상세 / 모델 실험실 / 파이프라인 허브 / 스모크테스트 리포트 등이 교체.

## 2. 사이드바 네비게이션 — 모듈 레지스트리 매핑

목업의 사이드바 항목을 `docs/02`의 `ModuleConfig` 및 `docs/03` Phase 정의에 매핑하면 아래와 같다. **이 표가 사실상 `modules` 테이블의 시드 데이터 초안**이다.

| 사이드바 라벨 | 매핑 모듈 (`modules.id`) | Phase | 비고 |
|---|---|---|---|
| 홈 | `main-gallery` (전시실) | 1 | `mainScreenSlot: hero+feed` |
| 프로젝트 | `my-projects` | 1 | 내 아티팩트 목록 |
| 갤러리 | `prompt-wiki` | 1 | 프롬프트 위키 전체보기 |
| 파이프라인 | `pipeline-hub` | 3 | 3D/숏폼/상세페이지/게임/카피라이팅 파이프라인 허브 |
| 모델 실험실 | `model-lab` | 2 | `status: 'new'` → 사이드바에 **NEW 배지** 노출 (목업에 실제 반영됨) |
| 스모크 테스트 | `smoke-test` | 4 | |
| 수익 & 정산 | `revenue-dashboard` | 4 | `payment_accounts`, `revenue_shares` 뷰 |
| 마켓플레이스 | `marketplace` | 4/5 | Phase4 입점형 + Phase5 매칭 동시 수용 |
| 커뮤니티 | `community` | 1 | 댓글/랭킹/팔로우 등 소셜 레이어 |
| 가이드 & 튜토리얼 | `academy` | — (전Phase 공통) | 바이브코딩 입문~출시 강의 (원 기획의 "지속적 콘텐츠 누적" 축) |

**NEW 배지 렌더링 규칙**: `modules.status === 'new'`이고 `new_until`이 지나지 않은 항목에 사이드바 라벨 옆 보라색 `NEW` 태그를 자동 부착한다 (`docs/06` "NEW 모듈 자동 노출" 로직과 동일 소스).

**사이드바 하단 고정 영역**
- 크레딧 잔액 위젯 (`credits.balance` 실시간 바인딩) + `충전하기` CTA → Phase 2 크레딧 시스템과 직결
- 계정 요약(아바타, 닉네임, 역할 라벨 "Creator") — `profiles` 테이블

## 3. 홈 화면 (전시실) — `main-gallery` 모듈

`docs/06`의 슬롯 구조를 그대로 따른다.

### 3-1. Hero 슬롯
- 카피: "아이디어를 만들고, 실험하고, 세상에 선보이세요" + 서브카피 "프롬프트 한 줄에서 시작해 수익화와 실제 매출 1원까지"(포지셔닝 문구를 UI 카피로 직접 노출 — `docs/01` 포지셔닝 선언문과 동일 메시지)
- 좌측: 헤드라인 + CTA 2개(`프로젝트 만들기` primary, `모델 실험실 열기` secondary/outline)
- 우측: 캐릭터 일러스트 + 부유 아이콘(게임 컨트롤러, 3D 큐브, 차트) — Phase 1/2/3을 시각적으로 암시하는 장식 요소, 실제 기능 아님

### 3-2. "오늘의 추천" — Feed 슬롯 (전Phase 아티팩트 통합)
- 카드 그리드(4열), 카드 하나는 `artifacts` 레코드 하나에 대응
- 카드 구성 요소: 썸네일/영상 프리뷰(재생 아이콘 오버레이 + 재생시간 배지 `02:36` 등), 카테고리 배지(`게임`), 제목, 작성자 핸들, 좋아요/조회수
- **핵심**: 이미지(사진), 영상(도시 시뮬레이션, 숏폼), 3D/게임(우주비행슈팅, 3D캐릭터)가 **같은 카드 컴포넌트, 같은 그리드**에 자연스럽게 섞여 노출됨 — `docs/02`에서 말한 "artifact.type에 따라 다른 미리보기 렌더러, 카드 레이아웃은 공통"의 실제 구현 예시
- 우상단 `모두 보기` 링크 → 갤러리(`prompt-wiki`) 전체 목록으로 이동

### 3-3. "빠른 시작 도구" — 퀵액션 바
- 아이콘 6개: 프롬프트 작성 / 모델 실험 / 3D 에셋 생성 / 숏폼 영상 만들기 / 상세페이지 제작 / 게임 만들기
- 각 아이콘은 해당 모듈의 `entryRoute`로 직결되는 바로가기. **이 목록도 modules 레지스트리에서 "quickAction: true" 플래그로 동적 구성**해야 함 — Phase 3에서 새 파이프라인이 추가되면 이 줄에도 자동으로 아이콘이 늘어나야 함

### 3-4. 우측 위젯 — "이번 달 사용 현황"
- 크레딧 사용량 `24,680 / 50,000`, 진행률 바(49%)
- Phase 2 크레딧 시스템(`credit_transactions`)의 월간 집계 뷰

## 4. 프로젝트 상세 페이지 — 아티팩트 상세 뷰

임의의 `artifacts` 레코드(예: 게임 타입) 클릭 시 진입하는 화면. **모든 artifact.type에 공용으로 쓰는 템플릿**이며, 상단 프리뷰 영역만 타입별 렌더러가 교체된다(`docs/07` 실행 엔진 라우팅 지점).

### 4-1. 헤더
- 브레드크럼 "프로젝트 / 우주 비행 슈팅 게임", 버전 태그(`v1.3.2`), `...` 더보기 메뉴
- 타이틀 + 공개상태 배지(`공개`), 한줄 설명
- 태그 리스트(자유 텍스트 태그: 게임/슈팅/아케이드 등)
- 작성자 정보 줄: 아바타, 핸들(`space_creator`), 최근 업데이트 시점, 통계 아이콘 3종(조회/좋아요/댓글)
- 액션 버튼: `플레이`(primary, 실행엔진 트리거) / `편집하기` / `공유` / `...`

### 4-2. 프리뷰 패널 (우측 대형 영역)
- **여기가 `IExecutionEngine`이 실제로 렌더링되는 자리** (`docs/07`)
- 게임이면 iframe sandbox 실행 화면 + 오버레이 HUD(SCORE/WAVE/HP는 게임 자체 UI, 플랫폼이 그리는 게 아니라 iframe 내부 콘텐츠)
- 하단에 플랫폼이 그리는 `게임 실행` CTA 오버레이 — 최초 클릭 전엔 정적 썸네일만 보여주고, 클릭 시 실행 엔진 기동 (리소스 절약 + 원치 않는 자동 실행 방지)

### 4-3. 탭 바
`개요 / 분석 / 수익 / 스모크테스트 / 댓글(37) / 버전 히스토리`
- **개요**: 프로젝트 소개, 기술 스택 태그
- **분석**: 성과 요약(방문수/플레이수/완주율/좋아요, 전월 대비 %) — Phase 4 이후 `revenue-dashboard`와 데이터 소스 공유
- **수익**: `revenue_shares` 뷰 (목업엔 탭만 존재, 상세 화면은 별도 정의 필요)
- **스모크테스트**: 해당 아티팩트에 연결된 `smoke_tests` 요약 카드(원형 게이지 78/100 "성공 가능성 높음" + `리포트 보기` → 8절 리포트 화면으로 딥링크)
- **댓글 / 버전 히스토리**: `comments`, `prompt_versions`(또는 아티팩트 버전 테이블) 그대로 사용

## 5. 모델 실험실 — `model-lab` 모듈 (Phase 2)

3컬럼 구조: **입력(좌) / 결과 그리드(중앙) / (선택 시) 게시 액션(하단)**

### 5-1. 좌측 입력 패널 — 단계형 폼
1. **프롬프트 입력**: textarea + 글자수 카운터(`46/1000`), `프롬프트 개선하기` 버튼(AI 보정 — Claude API 호출 지점)
2. **모델 선택 (다중 선택)**: 체크박스 리스트로 벤더 병렬 선택 (Midjourney v7, DALL-E 3, Stable Diffusion 3.5, Leonardo Phoenix) — `model_providers` 테이블 기반 동적 렌더링, 신규 벤더 추가 시 이 리스트에 자동 추가되어야 함
3. **설정**: 비율(1:1/16:9/9:16 라디오), 스타일 프리셋 드롭다운
4. 하단 고정 `생성하기` 버튼에 **필요 크레딧 수치를 실시간 계산해 노출**(`필요 크레딧 16`) — 선택된 모델 수 × 모델별 원가×마진 합산, 클릭 전에 비용을 투명하게 보여주는 것이 핵심 UX 원칙

### 5-2. 중앙 결과 그리드
- 선택한 모델 수만큼 컬럼 생성(가변 그리드, 최대 4~6열 후 줄바꿈)
- 컬럼 헤더: 모델명 + 소요 크레딧(`Midjourney v7 12크` 등) — `generation_jobs.credit_charged`를 결과 옆에 바로 노출해 "이 모델이 더 비싸다"는 판단을 돕는다
- 각 이미지 하단: 재생성/즐겨찾기 아이콘 + **선택 체크(원형 토글)** — 여러 결과 중 마음에 드는 것만 다중 선택 가능
- 최하단 바: `선택 이미지 N개` 카운터 + 다운로드 아이콘 + `전시실에 게시하기`(primary) → 선택된 결과를 `artifacts`로 승격하고 Phase 1 피드에 게시 (모듈 간 연결의 실제 예시: Phase2 결과물이 Phase1 전시실로 흘러감)

## 6. 파이프라인 허브 — `pipeline-hub` 모듈 (Phase 3)

- 헤더 카피: "AI 자동화 도구로 아이디어를 완성하세요"
- 카드 그리드(2열 기본, 카피라이팅처럼 설명이 긴 카드는 와이드 2배 폭 허용)
- 카드 구성: 픽토그램 아이콘(파이프라인 성격을 상징하는 일러스트) + 타이틀 + 1~2줄 설명 + `시작하기` 버튼
- 목업 노출 파이프라인: `3D 에셋`, `숏폼 영상`, `상세페이지`, `게임 개발`, `AI 카피라이팅` — 5개 모두 `pipelines` 테이블의 개별 레코드, **카드 자체가 하나의 모듈이므로 신규 파이프라인 출시 시 이 그리드에 카드 한 장만 추가되면 됨** (레이아웃 재설계 불필요 — `docs/02` 원칙 A의 실제 사례)
- `시작하기` 클릭 → 해당 파이프라인의 입력 폼(모델 실험실과 유사한 좌측 패널 구조 재사용 권장, 일관성 위해 컴포넌트 공유)

## 7. 스모크 테스트 리포트 — `smoke-test` 모듈 (Phase 4)

### 7-1. 상단 요약 카드
- 대상 아티팩트 썸네일 + 이름(`AI 여행 플래너 앱`) + 버전 + 변화율 배지(`+15.0`)
- 테스트 기간(`2026.08.20 - 2026.09.01`), 집행 예산(`₩150,000`)
- **원형 스코어 게이지**(`82/100`, "성공 가능성 매우 높음") — `smoke_test_reports.success_score` 시각화. 색상은 점수 구간별로 accent 컬러 톤 변화(고득점=보라/초록 계열, 저득점=경고색) 권장
- `PDF 다운로드` 버튼 — 오프라인 공유/투자 논의용 산출물

### 7-2. 탭 바
`요약 / 트래픽 / 반응 / 사용자 반응 / 페르소나 / 개선 제안`
- 요약 탭 기준 아래 요소 노출:
  - **핵심 지표 6분할 그리드**: 노출, 클릭, CTR, 회원가입, 결제전환, 예상 CAC — 각 지표에 전기간 대비 증감률 배지
  - **일별 방문자 & 가입 추이 라인 차트**: 두 시리즈(방문자/가입자) 오버레이
  - **핵심 인사이트 박스**(우측): AI가 생성한 불릿 3~4개(타겟 반응, 전환 포인트, 강조해야 할 기능) — `smoke_test_reports.recommendation`을 구조화해 표시
  - 하단 `개선 제안 보기` 링크 → 상세 개선 제안 탭으로 이동

이 화면이 `docs/01`에서 정의한 **"진짜 차별화 지점"의 최종 산출물**이다. 사업자등록·PG가입·광고 집행 없이 이 리포트 한 장을 받는 것이 Phase 4 전체의 핵심 가치 제안이므로, 디자인 우선순위도 이 화면이 가장 높다.

## 8. 공통 컴포넌트 인벤토리

| 컴포넌트 | 재사용 위치 | 비고 |
|---|---|---|
| Primary/Outline 버튼 | 전 화면 | Primary는 항상 accent 보라, Outline은 테두리만 |
| 아티팩트 카드 (썸네일+배지+통계) | 전시실 피드, 프로젝트 목록 | `artifacts.type`별 프리뷰 렌더러 분기 |
| 탭 바 | 프로젝트 상세, 스모크테스트 리포트 | 동일 컴포넌트, 탭 항목만 props로 교체 |
| 원형 스코어 게이지 | 스모크테스트, (향후) 매칭 성사율 등 | 점수 구간별 색상 규칙 공통 정의 필요 |
| 통계 그리드 카드(수치+증감%) | 프로젝트 분석, 스모크테스트 요약 | 증감률 양수=녹색, 음수=적색 |
| 단계형 좌측 입력 폼(1.2.3 번호) | 모델 실험실, 파이프라인 실행 화면 | 번호 매겨진 스텝 구조 재사용 |
| NEW/공개/베타 배지 | 사이드바, 카드, 리포트 | `modules.status`, `artifacts.status`와 동일 배지 스타일 |

## 9. 다크모드 대응

목업이 다크 테마 기준으로 제작되어 있으므로, `docs/06`의 시맨틱 토큰 원칙에 따라 **라이트 모드는 별도 디자인이 아니라 토큰 반전**으로 처리한다. 단, 다음 요소는 라이트 모드 시 대비 재검토가 필요하다.
- 보라색 accent 위 흰 텍스트 버튼 (라이트 배경에서도 명도 대비 유지)
- 게임/영상 프리뷰 카드의 다크 오버레이(썸네일 위 그라데이션) — 라이트 모드에서도 텍스트 가독성 유지 위해 오버레이는 테마 무관 고정 다크 처리 권장 (`docs/06`에서 이미 "카드 프레임만 테마 반응, 콘텐츠는 원본 유지" 명시)
