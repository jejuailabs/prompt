# 게임 게시물 → 플레이 흐름

2026-10-25 사용자 요청 반영. 게임 카드나 기존 `#game-play?id=...` 링크를 열면 게임 게시물이 먼저 표시된다.

- 게임 미리보기 이미지와 플레이 버튼, 제목·설명·조작 방법·제작자와 공유를 제공한다. PC는 미리보기와 설명을 나란히, 모바일은 위아래로 표시한다.
- 플레이 버튼을 누르기 전에는 실행 iframe을 만들지 않는다. 외부 HTML 프록시, 게임 실행 기록과 광고 연동도 이 단계에서 시작하지 않는다.
- 플레이 버튼을 누르면 기존 게임 모달을 연다. 게임 자체의 시작 안내·난이도 선택·음소거·일시정지·전체화면·랭킹·공유 기능은 그 실행 화면에서 사용한다.
- 실행 화면을 닫으면 같은 게시물로 돌아오고 플레이 버튼에 초점을 복원한다. 목록은 별도의 `게임 목록` 버튼으로 돌아간다. 다시 플레이하면 새로운 iframe을 만든다.
- 게시물 ID마다 화면을 새로 구성한다. 실행 중 다른 게시물로 이동하거나 이전 게시물로 돌아와도 플레이 버튼을 다시 눌러야 한다.
- 게임룸, 홈 카드, 즐겨찾기와 직접 링크는 기존 URL을 유지한다. 외부 퍼가기용 `/embed/{id}`의 실행 계약은 별개로 유지한다.

이 변경은 호스트의 게시물 UI와 실행 시점에 적용한다. 독립 게임 패키지를 변경하거나 재생성하지 않는다.

## 검증

`scripts/game-module-kit/game-post-qa.cjs`는 PC 1280×900, 모바일 390×780 및 320×568에서 실제 카드 클릭·직접 링크·설명/조작법·공유·플레이 전 실행 파일/프록시 요청 없음·실행 후 조작·닫기와 재실행·게시물 간 이동을 검사한다. 외부 게임은 로컬 모의 응답을 사용하며 운영 DB와 유료 API는 호출하지 않는다.

기존 공유/모달/퍼즐 브라우저 검사도 새 플레이 진입 단계를 거치도록 변경했다. 공개 사이트 배포는 포함하지 않는다.

검증 결과: 위 세 화면 크기의 브라우저 흐름 검사와 기존 발견·랭킹·공유·Godot 수명주기 회귀 검사 25개가 통과했다. Chromium 모바일 에뮬레이션으로 검사했으며 실기기 검사는 포함하지 않는다.

TypeScript noEmit과 게시물/목록/실행 화면 대상 ESLint도 통과했다. 게임 창을 닫고 다시 열 때 대기 중이던 광고 오버레이 상태가 남지 않도록 광고 연동 정리도 보완했다. 실제 광고 공급자는 호출하지 않았으며 기존 광고 어댑터 회귀 검사는 모의 SDK로 통과했다.
