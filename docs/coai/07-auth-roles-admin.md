# 07. 인증 · 회원 등급 · 어드민 모드

## 1. 로그인 방식
- **구글 로그인** (기본, 가장 쉬움)
- **이메일 + 비밀번호** (이메일 인증 필수)
- 카카오 로그인: 대상 연령층에서 수요가 높을 것으로 예상합니다(추정). Firebase Auth가 카카오를 기본 제공하지 않으므로 **OIDC 커스텀 제공자 또는 커스텀 토큰 방식**이 필요합니다. 구현 방법과 요금제 조건은 도입 시점에 확인합니다 (2단계 검토).
- 가입 직후 닉네임 설정 화면을 보여줍니다. 닉네임은 고유해야 하며, `nicknames/{nickname}` 문서로 중복을 막습니다.
- 가입할 때 이용약관과 개인정보 처리방침 동의를 받습니다 (필수 / 선택 구분).

## 2. 역할 (Role) — 권한

역할은 **Firebase custom claims**에 저장하고, 서버(규칙, API)에서 확인합니다. `users.role`은 화면 표시용 복사본입니다.

| 역할 | 할 수 있는 일 |
|---|---|
| `member` | 프롬프트·작품·커뮤니티 글 작성, 댓글, 좋아요, 신고 |
| `editor` | + 뉴스, 이벤트, 가이드, 배우기 콘텐츠 작성·수정, 스터디 운영 |
| `moderator` | + 신고 처리, 글 숨김, 작품 승인/반려, 회원 일시 정지 |
| `admin` | + 역할 부여, 사이트 설정, 배너, 도구 설정, 통계 전체 |

- 역할 변경은 `/api/admin/users/[uid]/role`에서만 할 수 있습니다 (admin만 호출 가능, `setCustomUserClaims`).
- 역할이 바뀌면 사용자의 토큰을 새로 고쳐야 반영되므로, 다음 요청 때 강제로 갱신합니다.
- 최초 관리자는 Firebase Admin 스크립트(`scripts/set-admin.ts`)로 지정합니다.

## 3. 회원 등급 (Level) — 카페식 동기 부여

권한과 별개로, 활동량에 따른 **표시용 등급**입니다.

| 등급 | 이름 (ko / en) | 아이콘 | 조건 (예시, 어드민에서 조정) | 혜택 |
|---|---|---|---|---|
| 1 | 새싹 / Sprout | 🌱 | 가입 | 기본 활동 |
| 2 | 잎새 / Leaf | 🌿 | 글 3 + 댓글 10 + 가입 7일 | 이미지 업로드 한도 증가 |
| 3 | 나무 / Tree | 🌳 | 포인트 300 | 바로쓰기 유료 도구 한도 증가 |
| 4 | 숲 / Forest | 🌲 | 포인트 1,000 + 채택 답변 5 | 가이드 > 팁 작성 (승인제) |
| 5 | 코파일럿 / Copilot | ✦ | 운영진 지정 | 스터디 운영, 우수 회원 배지 |

**포인트 지급 (예시)**: 글 +5, 댓글 +1, 프롬프트 등록 +10, 작품 승인 +30, 답변 채택 +20, 스터디 출석 +5, 받은 좋아요 +1 (하루 상한 50)

- 포인트와 등급은 **서버(API 라우트)에서만** 바꿉니다.
- 등급 아이콘은 닉네임 옆에 항상 표시합니다 (`LevelBadge`).

## 4. 회원 제재
- 신고 누적, 운영진 판단에 따라: 경고 → 7일 정지 → 영구 정지
- 정지하면 custom claim에 `banned: true`를 넣어 규칙에서 작성을 막습니다.
- 정지 사유와 기간은 본인에게 알림으로 보냅니다.

## 5. 어드민 모드

### 5.1 들어가는 방법
- 스태프(editor 이상)가 로그인하면 아바타 메뉴에 **"어드민 모드"**가 나타납니다.
- `/[locale]/admin/*` — `middleware.ts`가 세션 쿠키가 없으면 로그인으로 보내고, `admin/layout.tsx`가 서버에서 역할을 다시 확인합니다.
- 어드민 화면은 같은 디자인 토큰을 쓰지만 **왼쪽 사이드바 + 넓은 표** 레이아웃입니다. 상단에 "어드민 모드" 띠(브랜드 연한 배경)를 표시해 일반 화면과 구분합니다.
- **현장 편집 모드**: 어드민 모드가 켜진 상태로 일반 페이지를 보면, 콘텐츠 카드에 연필 아이콘(수정), 눈 아이콘(숨김), 핀 아이콘(추천)이 나타납니다. 홈 배너와 섹션도 그 자리에서 바로 고칠 수 있습니다.

### 5.2 메뉴 구성

| 메뉴 | 기능 | 최소 역할 |
|---|---|---|
| 대시보드 | 오늘 가입·글·댓글·실행 수, 승인 대기 수, 미처리 신고 수, **갱신 필요한 가이드**(최종 확인 90일 초과), 도구 사용량·비용 추정 | editor |
| 콘텐츠 관리 | 뉴스, 이벤트, 가이드, 배우기 작성·수정·예약 발행. 프롬프트·게시글 검색, 숨김, 추천 지정 | editor |
| 승인 대기열 | 만들어보기 작품, 우수회원 팁 글. 샌드박스 미리 실행 → 체크리스트 → 승인 / 반려(사유 필수) | moderator |
| 신고 처리 | 신고 목록, 대상 미리보기, 처리(숨김, 경고, 정지, 기각) | moderator |
| 배너 관리 | 홈 히어로 포스터 등록, 순서 드래그, 기간, 테마 선택, 미리보기(라이트/다크, PC/모바일) | editor |
| 스터디 관리 | 스터디 개설, 회차, 참여자, 출석, 과제 제출 현황 | editor |
| 회원 관리 | 검색, 역할 변경, 등급 수동 조정, 정지 | admin (정지는 moderator) |
| 바로쓰기 설정 | 도구별 켜기/끄기, 회원 등급별 일일 한도, 월 비용 상한 | admin |
| 사이트 설정 | 점검 모드, 인기 검색어, 공지 띠, 등급 조건, 포인트 규칙, 금칙어 | admin |
| 작업 기록 | 누가 언제 무엇을 바꿨는지 (`adminLogs`) | admin |

### 5.3 작품 승인 체크리스트 (승인 대기열)
- [ ] 샌드박스에서 실제로 실행되는가
- [ ] 로그인 화면, 결제 화면처럼 **실제 서비스를 흉내 낸 피싱 화면**이 아닌가
- [ ] 외부로 데이터를 몰래 보내거나, 채굴·과도한 CPU 사용이 없는가
- [ ] 코드나 화면에 API 키, 개인정보가 노출돼 있지 않은가
- [ ] 저작권 문제(다른 사람의 캐릭터, 음원, 로고)가 없는가
- [ ] 라이선스가 입력돼 있는가

### 5.4 어드민 API 보호
- 모든 `/api/admin/*`는 `requireRole('editor' | 'moderator' | 'admin')`을 먼저 실행합니다.
- 상태를 바꾸는 요청은 POST/PATCH/DELETE만 허용하고, 같은 출처(origin) 확인을 합니다.
- 모든 변경은 `adminLogs`에 `{ actorId, action, target, before, after, at }`로 남깁니다.
