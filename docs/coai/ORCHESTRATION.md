# COAI — 오케스트레이션 (프로젝트 총괄 지침)

## 1. 한 줄 정의

**COAI**: Co(함께·협업·커뮤니티)와 AI가 만나는, **"쉽게 보고, 바로 써보는 AI 커뮤니티"**입니다.
당근 모임 회원들과 함께 채워 가는 **스터디 겸 커뮤니티**이며, 주요 대상은 30대 중후반~60대 초반, 게시판·카페 문화에 익숙한 사용자입니다.

## 2. 절대 원칙 (모든 작업에 적용)

1. **디자인은 시안을 그대로 재현합니다.** 레이아웃, 간격, 컬러, 카드 형태는 `docs/03-design-system.md`를 기준으로 합니다. 임의로 "개선"하지 않습니다.
2. **알맹이는 최신, 겉모습은 익숙하게.** 목록·카드·게시판처럼 익숙한 UI를 쓰고, 실험적인 인터랙션은 넣지 않습니다.
3. **가독성 우선.** 본문 16px 이상, 보조 텍스트도 명도 대비 WCAG AA(4.5:1) 이상을 지킵니다.
4. **모든 UI 문자열은 다국어 키로 작성합니다.** 하드코딩된 한글을 컴포넌트에 직접 넣지 않습니다. (`docs/10`)
5. **모든 컬러는 디자인 토큰(CSS 변수)으로만 씁니다.** 다크/라이트 모드가 자동으로 대응하게 합니다. (`docs/03`, `docs/10`)
6. **남이 올린 코드는 절대 본 도메인에서 실행하지 않습니다.** 실행은 별도 도메인의 샌드박스에서만 합니다. (`docs/08`)
7. **비용이 드는 AI API는 로그인 + 사용량 제한 없이 공개하지 않습니다.** (`docs/09`)
8. **권한 확인은 서버(Firestore Rules / API Route)에서 합니다.** 클라이언트에서 숨기는 것만으로는 보안이 되지 않습니다. (`docs/07`)

## 3. 기술 스택 요약

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript |
| 호스팅 | Vercel (본 사이트) / 샌드박스는 별도 도메인 프로젝트 |
| 백엔드 | Firebase: Authentication, Firestore, Storage |
| 서버 로직 | Next.js Route Handlers (Vercel Functions) + Firebase Admin SDK |
| 스타일 | Tailwind CSS + CSS 변수 토큰 |
| 테마 | next-themes (light / dark / system) |
| 다국어 | next-intl (ko 기본, en) |

라이브러리 버전은 **설치 시점의 최신 안정 버전**을 공식 문서에서 확인한 뒤 고정합니다. 이 문서에는 버전을 적지 않습니다.

## 5. 작업 순서 (마일스톤)

각 단계가 끝나면 아래 "완료 기준"을 확인한 뒤 다음 단계로 넘어갑니다.

### M0. 기반
- [ ] Next.js 프로젝트 생성, Tailwind 설정, 폴더 구조 (`docs/05`)
- [ ] 디자인 토큰 CSS 변수 + 다크 모드 토큰 (`docs/03`, `docs/10`)
- [ ] next-themes 토글, next-intl 라우팅 `/ko`, `/en` (`docs/10`)
- [ ] Firebase 프로젝트 연결 (Auth, Firestore, Storage), Vercel 배포 파이프라인
- **완료 기준**: 빈 레이아웃(헤더, 푸터, 모바일 하단 탭)이 두 언어와 두 테마에서 깨지지 않고 Vercel 프리뷰에 배포됨

### M1. 홈 + 공통 컴포넌트 (시안 재현)
- [ ] 헤더, 히어로 포스터 캐러셀, 섹션 카드 3열, 커뮤니티 인기글, 모바일 레이아웃
- **완료 기준**: 시안 이미지와 나란히 놓고 비교했을 때 레이아웃·간격·컬러 차이가 없음 (`docs/03` 체크리스트)

### M2. 회원 + 어드민
- [ ] 로그인(구글, 이메일), 프로필, 회원 등급, 역할(custom claims)
- [ ] 어드민 모드: 대시보드, 콘텐츠 관리, 승인 대기열, 신고 처리, 배너 관리 (`docs/07`)

### M3. 1단계 메뉴
- [ ] 뉴스·이벤트, 프롬프트, 커뮤니티, 가이드, 바로쓰기(비용 없는 도구) (`docs/04`, `docs/09`)

### M4. 2단계 메뉴
- [ ] 만들어보기(정적 ZIP 실행), 배우기(커리큘럼 + 플레이어), 스터디방 (`docs/08`, `docs/09`)

### M5. 3단계 확장
- [ ] 같이보기(실시간), 영상 AI 질문, GitHub 빌드 실행, 유료 API 도구

## 6. 에이전트 작업 규칙

- 한 번에 **한 마일스톤의 한 항목**만 작업하고, 끝나면 체크박스를 갱신합니다.
- 새 컬렉션, 필드, 라우트를 추가하면 **해당 docs 문서를 함께 수정**합니다. 문서와 코드가 다르면 문서를 먼저 맞춥니다.
- 정해지지 않은 사항은 임의로 결정하지 말고 아래 "미결 사항"에 추가한 뒤 사람에게 묻습니다.
- 커밋 메시지: `feat(home): 히어로 캐러셀` 형식 (Conventional Commits)
