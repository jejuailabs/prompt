# 09. 바로쓰기 도구 · 배우기(학습 플레이어)

## Part A. 바로쓰기 (사이트 자체 도구)

### A1. 설계 원칙
1. **입력칸 하나, 버튼 하나, 결과 하나.** 옵션은 "고급 설정" 접이식 안에 숨깁니다.
2. **가능하면 브라우저 안에서 처리합니다.** 서버 비용이 없고 파일이 서버로 가지 않아 개인정보 걱정도 줄어듭니다.
3. 서버나 외부 AI API가 필요한 도구는 **로그인 + 일일 한도 + 월 비용 상한**을 반드시 겁니다.
4. 결과마다 [복사] [다운로드] [다시 하기] 버튼을 둡니다.

### A2. 도구 목록과 처리 방식

| 도구 | 경로 | 처리 위치 | 비용 | 로그인 | 단계 |
|---|---|---|---|---|---|
| QR 코드 생성 | `/tools/qr` | 브라우저 (예: `qrcode` 라이브러리) | 없음 | 불필요 | 1 |
| 이미지 변환 (형식, 크기, 압축) | `/tools/image-convert` | 브라우저 (Canvas) | 없음 | 불필요 | 1 |
| 글자 수 세기, 맞춤법 정리 보조 | `/tools/text` | 브라우저 | 없음 | 불필요 | 1 |
| URL 단축 | `/tools/shorten` | 서버 + Firestore | 낮음 | **필요** | 1 |
| TTS (글 → 음성) | `/tools/tts` | 1단계: 브라우저 Web Speech API / 2단계: 외부 TTS API | 1단계 없음 | 2단계부터 필요 | 1→2 |
| STT (음성 → 글) | `/tools/stt` | 외부 STT API | 있음 | 필요 | 2 |
| 문서 요약 | `/tools/summarize` | 외부 AI API | 있음 | 필요 | 2 |
| 배경 제거 | `/tools/remove-bg` | 브라우저 내 모델 또는 외부 API (검토) | 검토 | 검토 | 3 |

- 브라우저 Web Speech API의 한국어 음성 품질은 **브라우저와 운영체제마다 다릅니다.** 1단계에서는 "기기 음성"이라고 안내합니다.
- 외부 API 업체(TTS, STT, 요약 모델)는 도입 시점에 품질과 요금을 비교해 정합니다. 이 문서에는 특정 업체나 요금을 적지 않습니다.

### A3. URL 단축 악용 방지
URL 단축은 피싱 링크를 숨기는 데 자주 악용됩니다.
- 회원만 생성 가능, 하루 20개 제한
- 짧은 주소로 이동하기 전에 **중간 안내 페이지**를 보여줍니다: "다음 주소로 이동합니다: {원래 URL}"
- 도메인 차단 목록 + 신고 기능, 신고되면 즉시 비활성화
- 저장 형식: `shortLinks/{code}` `{ url, ownerId, clicks, active, createdAt }`

### A4. 사용량 제한 (서버 도구 공통)
```
요청 → 세션 확인 → 정지 회원 차단
     → toolUsage/{오늘}_{uid}.counts[tool] < 등급별 한도 ?
     → 월 누적 비용 < 어드민 설정 상한 ?
     → 처리 → 사용량 +1 (트랜잭션)
```
| 등급 | 요약 | STT (분) | TTS (자) |
|---|---|---|---|
| 1~2 | 5회/일 | 5분/일 | 2,000자/일 |
| 3~4 | 20회/일 | 20분/일 | 10,000자/일 |
| 5, 스태프 | 50회/일 | 60분/일 | 30,000자/일 |

> 위 수치는 **예시**입니다. 어드민 > 바로쓰기 설정에서 조정하며, 월 비용 상한에 도달하면 해당 도구는 자동으로 "오늘은 사용량이 모두 찼어요" 상태가 됩니다.

- 입력 크기 제한: 요약 문서 최대 20,000자 또는 PDF 10쪽, STT 파일 최대 25MB
- 업로드한 파일은 처리 후 바로 삭제하고, 이 사실을 화면에 안내합니다.

## Part B. 배우기 (학습 플레이어)

### B1. 콘텐츠 구조
```
course (커리큘럼)  ─┬─ lesson 1 → video (유튜브 ID)
                    ├─ lesson 2 → video
                    └─ ...
playlist (주제별 묶음) → videos
study (스터디방) → sessions → (자료: videos, guide 링크) + 과제
```
- 운영진(editor)이 유튜브 URL을 붙여 넣으면 서버가 **YouTube Data API**로 제목, 채널, 길이, 썸네일을 가져와 `videos`에 저장합니다.
- 진행률: `users/{uid}/progress/{courseId}` `{ completedLessons: string[], lastVideoId, lastPosition }`

### B2. AI 학습 플레이어 화면 `/learn/watch/[videoId]`
```
┌──────────────────────────────┬──────────────────────┐
│                              │ [요약][목차][AI 질문][메모] │
│     YouTube IFrame Player    │                      │
│                              │  (선택한 탭 내용)       │
├──────────────────────────────┤                      │
│ 제목 · 채널 · 다음 강의 ›       │                      │
│ 타임스탬프 댓글                 │                      │
└──────────────────────────────┴──────────────────────┘
모바일: 플레이어 위, 탭은 아래로 쌓음
```
- 영상 재생은 **YouTube IFrame Player API**로 임베드합니다 (영상 파일을 직접 저장하지 않음).
- **목차(타임스탬프)**: 누르면 해당 시간으로 이동 (`player.seekTo`)
- **타임스탬프 댓글**: 댓글을 쓸 때 현재 재생 시간을 함께 저장, 누르면 그 장면으로 이동
- **메모**: 개인 메모, 현재 시간 자동 기록 (`users/{uid}/notes`)

### B3. 요약 · 목차 · AI 질문의 원천 데이터 — ⚠️ 확인 필요

> **유튜브 자막을 자동으로 가져오는 방법에 정책상 불확실성이 있습니다.**
> 제가 아는 범위에서는 YouTube Data API의 자막 다운로드(captions)는 **영상 소유자 권한이 필요한 것**으로 알고 있습니다. 비공식적으로 자막을 긁어오는 방식은 유튜브 서비스 약관에 어긋날 수 있습니다. 이 내용은 **확실하지 않음**으로 두고, 개발 전에 YouTube API 서비스 약관과 개발자 정책을 직접 확인해야 합니다 (ORCHESTRATION Q3).

정책 확인 전까지 쓸 수 있는 **안전한 대안**:
1. **운영진 작성 방식 (1단계 기본)**: 운영진이 영상을 보고 목차와 요약을 직접 작성하거나, 운영진이 자막 텍스트를 붙여 넣으면 AI가 초안을 만들고 사람이 검수합니다.
2. **본인 채널 영상**: 모임 운영진이 직접 올린 유튜브 영상은 소유자 권한으로 공식 API를 통해 자막을 가져올 수 있습니다 (권한 범위는 확인 필요).
3. **영상 설명란의 타임스탬프**: 많은 강의 영상이 설명란에 챕터를 적어 둡니다. Data API로 설명란을 읽어 `00:00 제목` 형식을 목차로 변환합니다.

저장 형식: `videos/{id}` `{ youtubeId, title, channel, duration, chapters: [{t, title}], summary: {ko, en}, transcriptSource: 'manual' | 'owner-api' | 'description', aiReady: boolean }`

### B4. AI 질문 (2~3단계)
- 질문 범위: **해당 영상의 요약·목차·운영진이 넣은 자막 텍스트** 안에서만 답합니다. 근거가 없으면 "영상에서 다루지 않은 내용이에요"라고 답하도록 프롬프트를 설계합니다.
- 답변에 관련 타임스탬프를 붙여 누르면 그 장면으로 이동합니다.
- 비용 제한은 A4 규칙을 따릅니다 (도구 이름 `video-qa`).

### B5. 스터디방
- 회차(`sessions/{n}`): `{ title, date, materials: [{type:'video'|'guide'|'link', ref}], assignment: { description, submitType: 'prompt'|'project'|'post', dueAt } }`
- 과제 제출: 해당 작성 화면으로 이동하면 `studySessionRef`가 자동으로 채워집니다. 제출물은 회차 페이지에 모여 보입니다.
- 출석: 오프라인 모임에서 운영진이 체크하거나, 회차 페이지에서 본인이 체크하고 운영진이 확인합니다.
- 스터디가 끝나면 "수료" 배지를 프로필에 표시합니다.

### B6. 같이보기 (3단계)
- 방장이 재생, 일시정지, 이동하면 참여자 화면이 따라갑니다. 오른쪽에 실시간 채팅을 둡니다.
- 구현 후보: Firebase Realtime Database (방 상태 동기화에 적합) 또는 Firestore 실시간 리스너
- 동기화 상태: `watchRooms/{roomId}` `{ videoId, hostId, state: 'playing'|'paused', position, updatedAt }`
- 참여자는 `position + (지금 − updatedAt)`으로 위치를 보정합니다. 차이가 2초를 넘으면 맞춥니다.
- PC통신 "대화방" 감성: 입장·퇴장 알림 문구, 닉네임 옆 등급 아이콘
